# 后续开发待办

这是下一阶段的工作记录。目标是让 Code2Graph 能够服务于代码翻译主程序：每次翻译至少形成一条可实时验证的完整功能链，并能够在测试失败后可靠地反向定位 Source code。

## 1. 完成翻译闭环（最高优先级）

- [x] 明确“功能链”的定义：从入口文件/函数出发，覆盖运行所需的依赖文件，并包含对应的测试路径。
- [x] 在现有文件依赖图和翻译顺序的基础上，实现按功能链组织的翻译批次。
- [x] 支持调用方提出“继续翻译 N 个文件”时，自动扩展到能够形成完整测试闭环的文件集合。
- [x] 返回本次推荐翻译文件、扩展原因、关联测试和未满足的依赖。
- [x] 用小型仓库补充端到端测试，确认规划结果能够提供实时测试所需的静态前提。

## 2. Ground Truth 与动态验证

- [ ] 明确检索结果的 Ground Truth：区分“RAG 找到了相似测试”和“该测试确实验证了目标 Source function”。
- [ ] 以真实翻译失败为场景：Target 测试报错后，使用测试反向定位 Source test，再定位 Source function。
- [ ] 复用动态映射和 coverage 信息验证测试实际执行了哪些 Source function。
- [ ] 设计静态映射、RAG 检索和动态执行三者的证据与置信度字段。
- [ ] 在小型可控项目上建立可复用评估流程，避免把未经验证的检索结果当成 Ground Truth。
